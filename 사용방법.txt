TurnOff-Office-Update — macOS 사용 설명서

1. 다른 Mac에서 실행하기

터미널에 다음 한 줄을 붙여 넣으면 최신 main 브랜치의 스크립트를 내려받아 실행합니다.

  curl -fsSL https://raw.githubusercontent.com/hungryZoo/TurnOff-Office-Update/main/TurnOff-Office-Update.command -o TurnOff-Office-Update.command && bash TurnOff-Office-Update.command turnoff

자동 업데이트를 다시 켜려면 다음 한 줄을 실행하세요.

  curl -fsSL https://raw.githubusercontent.com/hungryZoo/TurnOff-Office-Update/main/TurnOff-Office-Update.command -o TurnOff-Office-Update.command && bash TurnOff-Office-Update.command turnon

TurnOff-Office-Update.command 파일 하나만 해당 Mac으로 옮기면 됩니다.
Finder에서 더블 클릭하면 자동 업데이트 차단을 적용합니다.
터미널에서 Mac 관리자 암호를 요구합니다. 입력 중 글자가 보이지 않는 것은 정상입니다.
다운로드한 실행 파일에 대한 macOS 차단 안내가 나타나면, 아래 터미널 방식으로 실행하세요.
일반적인 업데이트 설정 변경에는 추가 프로그램, Python, Homebrew, Codex 설치가 필요 없습니다.

터미널에서 다음 내용을 입력하고, 파일을 터미널로 드래그한 뒤 엔터를 누르셔도 됩니다.

  bash [여기에 TurnOff-Office-Update.command 파일을 드래그]

2. 끄기 / 켜기 / 상태 확인 / 최초 상태 복원

터미널에서 스크립트가 있는 폴더로 이동한 뒤 실행합니다.

  bash TurnOff-Office-Update.command turnoff
  bash TurnOff-Office-Update.command turnon
  bash TurnOff-Office-Update.command status
  bash TurnOff-Office-Update.command banner-status
  bash TurnOff-Office-Update.command restore

끄기 작업을 미리 보기만 하려면:

  bash TurnOff-Office-Update.command dry-run

status와 dry-run은 설정을 변경하지 않으며 관리자 권한도 요구하지 않습니다.
banner-status도 읽기 전용이며, macOS 13 이상과 Xcode 또는 Command Line Tools의 Swift가 필요합니다.
다른 동작에는 Swift가 필요하지 않습니다.
turnoff, turnon, restore는 관리자 권한이 필요합니다.
로그인된 일반 Mac 사용자 계정에서 실행하세요. root 직접 실행과 원격 SSH 실행은 대상이 아닙니다.

3. 실제로 하는 작업

현재 사용자와 시스템 공용 Microsoft AutoUpdate 설정 두 곳에 다음을 기록합니다.

  HowToCheck = Manual
  StartDaemonOnAppLaunch = false

turnon은 사용자와 시스템 공용 설정을 다음 값으로 바꿉니다.

  HowToCheck = AutomaticDownload
  StartDaemonOnAppLaunch = true

turnon은 자동 확인·다운로드·설치를 켭니다.
MAU 서비스 파일이 없으면 설정을 바꾸기 전에 중단합니다.

그리고 macOS의 launchctl로 다음 서비스를 비활성화하고, 등록되어 있으면 실행 등록을 해제합니다.

  gui/<현재 사용자 UID>/com.microsoft.update.agent
  system/com.microsoft.autoupdate.helper

launchctl disable은 재부팅 후에도 유지되는 차단 설정입니다.
bootout은 현재 로그인 세션/시스템에 등록된 서비스를 내려 즉시 실행되지 않게 합니다.
turnon은 두 서비스를 launchctl enable로 활성화하고, 필요하면 bootstrap으로 다시 등록합니다.

HowToCheck=Manual은 Office의 자동 업데이트 확인을 수동으로 전환합니다.
Microsoft 문서에 따르면 이 값만 설정하면 업데이트 도구 자체의 확인은 남을 수 있습니다.
따라서 서비스 차단도 함께 적용합니다.
StartDaemonOnAppLaunch는 추가 호환 설정입니다.
현재 Microsoft MAU 공식 환경설정 문서에는 이 키가 없으므로,
이 키 하나에 의존하지 않고 서비스 비활성화와 등록 해제 결과를 확인합니다.

문서, 로그인 정보, 키체인, 라이선스 서비스, Office 앱 파일은 삭제하거나 변경하지 않습니다.
VS Code, Edge, OneDrive의 별도 업데이트 설정은 이 스크립트의 대상이 아닙니다.

4. 백업과 복원 범위

처음 turnoff 또는 turnon을 실행할 때만 다음 위치에 기존 설정을 백업합니다.

  /Library/Application Support/TurnOff-Office-Update/active

백업은 해당 Mac에 보관되며 관리자만 읽을 수 있습니다.
다시 turnoff 또는 turnon을 실행해도 최초 백업을 덮어쓰지 않습니다.
restore는 두 설정 키와 두 서비스의 비활성화/실행 등록 상태만 최초 상태로 되돌립니다.
그 외의 최신 환경설정은 백업으로 덮어쓰지 않습니다.
원래 없던 설정 키는 삭제합니다.
원래 비활성화되어 있던 서비스는 복원 후에도 비활성화된 상태가 됩니다.
복원 후 백업은 같은 폴더 아래 restored-날짜-식별자 폴더에 보관됩니다.
launchctl에 명시적 상태가 없었던 경우, 복원 시 같은 효과의 enabled/disabled 상태를 기록합니다.

이전에 수동으로 차단한 Mac에서 이 스크립트를 처음 실행하면,
이미 차단된 상태가 백업됩니다. 이 경우 restore로 자동 업데이트가 켜지지는 않습니다.
스크립트 설치 이전에 수행한 수동 작업까지 추정해서 복원하지는 않습니다.
자동 업데이트를 켜려면 turnon을 사용하세요. turnon 이후에도 최초 백업은 유지됩니다.

여러 사용자 계정이 있는 Mac에서는 시스템 도우미 차단이 모든 사용자에게 영향을 줍니다.
사용자 에이전트 차단은 실행한 계정에만 적용됩니다.
다른 계정의 백업이 있으면 덮어쓰지 않고 중단합니다.

5. 적용 후 확인

status 실행 결과에서 다음을 확인하세요.

  user: HowToCheck = Manual
  user: StartDaemonOnAppLaunch = 0
  system: HowToCheck = Manual
  system: StartDaemonOnAppLaunch = 0
  .../com.microsoft.update.agent: disabled, unloaded
  system/com.microsoft.autoupdate.helper: disabled, unloaded

Office/MAU를 재설치한 뒤에는 status로 상태를 다시 확인하고 필요하면 turnoff를 재실행하세요.
회사/학교 관리 프로파일이 업데이트 정책을 강제하면 로컬 설정보다 우선할 수 있습니다.
Mac App Store에서 설치한 Office의 업데이트는 App Store가 관리하므로 별도입니다.
이 스크립트는 App Store 설정을 변경하지 않습니다.
자동 보안 업데이트도 차단되므로 필요한 업데이트는 직접 관리해야 합니다.
MAU를 사용하려면 turnon으로 켜거나 restore로 이전 서비스 상태를 복원하세요.

참고: Microsoft 공식 MAU 환경설정 문서
https://learn.microsoft.com/en-us/microsoft-365-apps/mac/mau-preferences

6. Office 실행 시 업데이트 오류 배너 진단과 수동 우회

백그라운드 허용을 끈 상태에서 Microsoft 자동 업데이트를 백그라운드에서
실행하도록 허용하라는 배너가 뜨면 다음 읽기 전용 진단을 실행하세요.

  bash TurnOff-Office-Update.command banner-status

SMAppService.statusForLegacyPlist(at:)로 다음 파일의 상태를 확인합니다.

  /Library/LaunchAgents/com.microsoft.update.agent.plist

파일이 있고 상태가 2 (requiresApproval, 사용자 승인 필요)이며
아래 백업 경로가 비어 있을 때만 수동 이동 명령을 안내합니다.
turnoff로 자동 업데이트를 끈 상태에서 Excel, Word, PowerPoint를 완전히 종료하고 실행하세요.

  sudo /bin/mv -n "/Library/LaunchAgents/com.microsoft.update.agent.plist" "/Users/Shared/com.microsoft.update.agent.plist.bak"

-n은 기존 파일을 덮어쓰지 않습니다. banner-status를 다시 실행해
원본 없음 / 백업 있음을 확인한 후 Office를 다시 열어 배너가 사라졌는지 확인하세요.
이동 후 SMAppService 상태가 특정 값으로 바뀐다고 가정하지 않습니다.
이 방법의 배너 제거 효과는 Office 버전별로 직접 확인해야 합니다.
파일 이동은 자동 업데이트 설정이나 백그라운드 허용을 켜지 않습니다.
시스템 공용 파일을 옮기므로 Mac의 다른 사용자에게도 영향을 줍니다.

되돌리려면 Office를 완전히 종료하고 다음을 직접 실행하세요.

  sudo /bin/mv -n "/Users/Shared/com.microsoft.update.agent.plist.bak" "/Library/LaunchAgents/com.microsoft.update.agent.plist"

banner-status로 원본 있음 / 백업 없음을 확인하세요.
두 파일이 모두 있으면 기존 파일을 덮어쓰지 말고 두 파일을 먼저 확인하세요.
turnon 또는 restore 전에 이 수동 백업을 원래 위치로 되돌려야 합니다.
원본이 없고 백업만 있으면 스크립트는 설정 변경 전에 중단하고 복원 명령을 안내합니다.
이 백업은 최초 설정 백업과 별개이며 스크립트가 자동 이동하거나 삭제하지 않습니다.
Office 또는 MAU 재설치로 파일이 다시 생기면 배너가 재발할 수 있습니다.

참고: Apple ServiceManagement API
https://developer.apple.com/documentation/servicemanagement/smappservice/statusforlegacyplist(at:)
